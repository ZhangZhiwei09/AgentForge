# ADR-002: 五层校验管线的分层逻辑

**日期:** 2026-06-13  
**状态:** 已采纳  
**决策者:** AgentForge Team

---

## 背景

LLM 生成的客服回复存在三类典型故障模式：
1. **格式故障**：输出自由文本而非结构化 JSON，或缺失必要字段
2. **幻觉故障**：编造不存在的政策、价格、流程
3. **越界故障**：输出了 prompt 禁止的内容（如虚假权威引用）

需要设计一个校验体系来逐层拦截这些故障——但每层校验都有成本和能力边界，需要明确"哪一层解决什么问题"以及"为什么是 N 层"。

## 考虑的方案

### 方案 A：单一 LLM-as-Judge 校验

用一个独立的 LLM 调用评估回复质量。

**优势:**
- 语义理解强，能发现复杂幻觉
- 实现简单，一个 prompt 搞定

**劣势:**
- LLM 自己也会犯错——用 LLM 校验 LLM 会引入第二层不可靠性
- 每次校验增加 ~200ms 延迟和额外 token 成本
- 对格式错误（如 JSON 不可解析）的检测反而不可靠
- 无法检测"KB 命中率"这种统计性指标

### 方案 B：纯规则校验

只用正则和 Schema 做检查。

**优势:**
- 零延迟、零成本、100% 确定
- 对格式错误的检测绝对可靠

**劣势:**
- 正则无法判断语义——"退货期限为 30 天"的正则会通过，但 KB 写的是 7 天
- 无法评估回复与 KB 的对齐程度

### 方案 C：五层分层校验（当前方案）

| 层级 | 校验内容 | 故障时策略 | 设计理由 |
|---|---|---|---|
| L1 | JSON 可解析 | 重试（换 temperature） | 格式错误是最便宜的拦截点——如果 LLM 没输出 JSON，后面都不用看 |
| L2 | Zod Schema 校验 | 重试 | 字段缺失/类型错误是 LLM 的常见低级错误 |
| L3 | 禁止行为正则扫描 | 拒绝，重试 | 直接针对已知幻觉模式（虚假权威、推测原因）|
| L4 | KB 文本命中率 | 软告警（不阻断） | 关键词重叠是弱信号，阻断会制造假阳性 |
| L5 | KB 为空 + 含事实数字 | 硬拒绝 | 无 KB 时出现数字 = 100% 编造，可以安全阻断 |

## 决策

**采纳方案 C（五层分层校验），L4 后续升级为 citation-based 逐句语义对齐。**

## 理由

1. **出错成本决定拦截策略**：L1-L3 的出错成本低（一次 LLM 重试），所以可以激进拦截。L4 的假阳性成本高（可能把正确回复误判为幻觉），所以只用软告警。L5 的假阳性率极低（无 KB 却出现数字，在客服场景下不可能合法），所以可以安全硬拦截。

2. **分层设计允许独立进化**：L4 从关键词重叠升级到 citation-based 语义对齐，不需要改动其他 4 层。每层是一个独立的 concern。

3. **拒绝单一 LLM-as-Judge 方案**：不是因为 LLM 不能做语义判断，而是因为把校验逻辑交给 LLM 意味着校验质量也受 LLM 不确定性的影响。规则层（L1-L3, L5）提供确定性基线，LLM 校验只应该作为补充层（L4+）而非替代层。

## 已知局限

**L4 关键词重叠无法检测"看了 KB 但篡改数字"的幻觉。** 如 LLM 将 KB 中的"7 天退货"改为"30 天退货"，只要包含"退货"关键词，L4 就会判为命中。这是当前方案已知的安全性盲区，需要在下一迭代中用 citation-based 逐句语义对齐替代。

## 拒绝的方案

**单一 LLM-as-Judge（方案 A）** 被拒绝，因为它在可靠性和成本两个维度上都不可接受——把质量控制完全交给不可靠的 LLM 是一个自我否定的设计。

**纯规则校验（方案 B）** 被拒绝，因为它无法覆盖语义层面的幻觉检测。
