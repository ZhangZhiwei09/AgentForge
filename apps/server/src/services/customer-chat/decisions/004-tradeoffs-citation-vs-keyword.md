# ADR-004: Citation 校验 vs 关键词校验 —— 为什么 L4 需要升级

**日期:** 2026-06-13  
**状态:** 方案已定，实施中  
**决策者:** AgentForge Team

---

## 背景

五层校验的 L4 层当前使用关键词重叠来判断回复是否"参考了 KB"。这个方案已知存在盲区：

- LLM 将 KB 中的"7 天退货"篡改为"30 天退货"——因为含"退货"关键词，L4 判为命中
- LLM 基于 KB 中不相关的内容自由发挥——因为任意几个词重叠，L4 判为命中

需要决定 L4 的升级方向。

## 考虑的方案

### 方案 A：保持关键词重叠（现状）

简单的 subword/ngram 匹配。

**优势:**

- 零延迟
- 零成本
- 实现简单

**劣势:**

- 无法检测篡改数字的幻觉（这是最危险的幻觉类型）
- 假阴性高（实际未参考 KB 但被误判为参考了）

### 方案 B：Citation-based 逐句语义对齐

将 LLM 回复拆分为句子，每句与 KB chunks 做 embedding 相似度计算。

**优势:**

- 语义级匹配，能检测"看起来相似但实质不同"的篡改
- 可产生可解释的引证分数（每句的来源归属）
- 假阳性率显著低于关键词方案

**劣势:**

- 每次校验需要 N × M 次 embedding 计算（N=回复句子数，M=KB chunk 数）
- 增加 ~200-500ms 延迟
- 依赖 embedding 模型质量

### 方案 C：混合方案

关键词做快速初筛（L4a），仅对"含事实指标但无关键词命中"的句子触发 embedding 校验（L4b）。

**优势:**

- 兼顾性能和准确性
- 大多数情况关键词够用，少数需要深度校验

**劣势:**

- 两层逻辑增加复杂度
- 关键词初筛仍存在漏报

## 决策

**采纳方案 C（混合方案），分两阶段实施：**

**Phase 1（当前实施）：** 保留 L4 关键词硬告警，新增 L4b Citation 语义校验层。对每个含事实性指标的句子，计算与 KB chunks 的 embedding 余弦相似度。相似度 < 0.7 的句子标记为"未找到引证来源"。

**Phase 2（规划中）：** 引入轻量 reranker（如 BGE-reranker），对 embedding 初筛的 top-3 chunks 做精排，输出最终的引证分数。

## 关键 Trade-off 分析

### 为什么不直接用 LLM 做引证校验？

用 LLM 校验 LLM 的幻觉——这存在两个问题：

1. **循环不可靠性**：校验 LLM 也会产生幻觉。如果它错误地认为句子有引证支撑，假阴性就直接通过了。
2. **成本和延迟**：每句一次 LLM 调用意味着 3-5 次额外调用，延迟和成本不可接受。

Embedding 相似度虽然不如 LLM 聪明，但它是确定性的、可审计的、成本极低的。

### 为什么阈值选 0.7 而不是 0.8 或 0.6？

0.7 是从 embedding 模型的 benchmark 中取的常用阈值（对应 bge-large-zh 的"语义相关但可能不精确匹配"边界）。这个值会随实际数据调优，当前作为初始值。

### 什么时候这个方案对客户"不可见"？

当 citation score 低于阈值但回答实际上是正确的——这是假阳性。当前策略：假阳性只触发软告警（记入 eval 日志），不阻断回复。只有当某个意图分类的 citation score 系统性偏低（如平均 < 0.5），才触发人工审查。

## 后果

- 每次 BusinessAgent 调用增加 ~300ms（3 句子 × 3 chunks × embedding 计算）
- 缓存 KB chunk embeddings（KB 不常变），实际延迟可降至 ~100ms
- eval 日志新增 `citation_scores` 字段，记录每句的引证分数
- 预计将"篡改数字"类幻觉的检出率从 ~30%（关键词）提升到 ~80%（语义对齐）
