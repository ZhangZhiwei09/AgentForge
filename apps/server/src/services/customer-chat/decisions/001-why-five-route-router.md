# ADR-001: 五路 Router 架构 vs ReAct 自主决策

**日期:** 2026-06-13  
**状态:** 已采纳  
**决策者:** AgentForge Team

---

## 背景

客服对话系统需要将用户消息分类并路由到不同的处理逻辑。存在两种范式：
1. **分类器路由（Classifier Router）**：先分类，再分发到专用处理器
2. **ReAct 自主决策**：让 LLM 在 ReAct 循环中自行判断需要什么工具/知识

## 考虑的方案

### 方案 A：纯 ReAct 自主决策

每条消息直接进入 AgentService.run()，LLM 自行决定查 KB 还是调工具。

**优势:**
- 架构简单，一个循环处理所有情况
- 边界模糊的问题（"我的东西什么时候到"）LLM 可以灵活处理
- 不需要维护分类规则

**劣势:**
- SAFETY 违规消息会进入 LLM（等于把危险输入递给模型）
- 简单问候也要走一次 LLM 调用（延迟 + 成本）
- 每次决策需要 200-500 tokens 推理，5 条消息就是 2500 tokens
- LLM 可能做出错误的工具选择（幻觉在决策层同样存在）
- 无法对不同类型的消息做差异化的安全和质量控制

**单次调用成本估算（GPT-4o-mini）：**
- 分类推理：~300 tokens 输入 + ~100 tokens 输出 ≈ $0.0001
- 对比：专用 Router LLM（jsonMode，60 tokens 输出）≈ $0.00002
- 日活 1000 用户 × 人均 10 轮对话 = 10000 次调用/天
- 年差额：$292 vs $73（Router 方案节省 75%）

### 方案 B：五路 Classifier Router（当前方案）

先分类到 5 条路径，每条路径独立实现。

**优势:**
- SAFETY 零 LLM 调用即可拒绝
- 问候/感谢/道别正则零延迟命中
- 每条路径可以针对性优化（RAG vs 工具 vs 人工）
- 安全边界清晰：SAFETY 路径不经过 LLM

**劣势:**
- 5 个 Agent 类需要维护
- 模糊边界可能被错分
- 需要维护路由规则

### 方案 C：混合方案（Router + ReAct fallback）

Router 分类后，不确定的再走 ReAct。

**优势:**
- 兼顾确定性和灵活性
- 低置信度时有兜底

**劣势:**
- 增加了一层复杂度
- 延迟叠加（Router → ReAct）

## 决策

**采纳方案 B（五路 Classifier Router），并保留未来引入方案 C 的扩展点。**

## 理由

1. **安全不可妥协**：SAFETY 违规消息必须在进入任何 LLM 之前被拦截。ReAct 方案无法保证这一点——LLM 可能被 prompt injection 诱导绕过安全检查。

2. **成本优势是真实的**：正则快速通道 + 关键词路由覆盖 60-70% 的请求，这些请求完全不消耗 LLM token。在高并发客服场景中，7 位数的年化节省。

3. **差异化质量控制**：每条路径的错误模式不同——BUSINESS 的幻觉是编造政策，TOOL 的幻觉是调用错误工具。分路径处理允许针对性的防护策略。

4. **架构扩展性**：RouteAgent 接口天然支持新增路径。如果未来需要增加"多语言翻译"路径或"情绪安抚"路径，无需修改现有 Agent。

## 后果

- 需要维护 5 个 Agent 类（当前总计 ~600 行，可接受）
- 需要维护路由分类规则（已通过"常见误分类提醒"章节做经验沉淀）
- 模糊边界问题通过 LLM Router + fallback 链缓解
- 预留了方案 C 的扩展点：RouterDecision 中的 confidence 字段可用于触发二次确认

## 拒绝的方案

**纯 ReAct 自主决策（方案 A）** 被拒绝，因为它在安全性、成本和可控性三个维度上都弱于 Router 方案。AI Agent 的自主性应该在安全边界内发挥作用，而不是替代安全边界。
