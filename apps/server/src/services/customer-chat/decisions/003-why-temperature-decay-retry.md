# ADR-003: Temperature 递减重试策略

**日期:** 2026-06-13  
**状态:** 已采纳  
**决策者:** AgentForge Team

---

## 背景

BusinessAgent 的 LLM 调用可能因格式错误、禁止行为命中或校验失败而需要重试。普通重试（相同参数重跑）在 LLM 场景下效果很差——如果模型在某次调用中"决定"不输出 JSON，用相同参数再跑大概率还是不输出 JSON。

需要设计一个让每次重试都有意义的策略。

## 考虑的方案

### 方案 A：简单重试（固定 temperature=0.3）

三次重试用相同参数。

**优势:** 实现简单

**劣势:**

- LLM 的"状态"在相同参数下高度确定——第一次输出非 JSON，后面大概率也是
- 浪费 token 和延迟，实际减少故障率有限

### 方案 B：Temperature 递增（0.0 → 0.3 → 0.7）

从确定到发散。

**优势:** 最终一定能产生输出

**劣势:**

- 高 temperature 下编造风险剧增
- 与"防幻觉"的核心理念相悖——你在让模型更"敢编"
- 第三次重试的高 temperature 输出大概率通不过 L3 禁止行为扫描

### 方案 C：Temperature 递减（0.3 → 0.1 → 0.0，当前方案）

从发散到确定。

**优势:**

- 第一次给一定创造性（0.3），让回复自然
- 失败后逐步收敛到确定性输出（0.0），提高格式合规率
- 与校验管线配合：格式错误 → 更确定 → JSON 合规率上升

**劣势:**

- 如果 temperature=0.0 仍然失败，后续没有调参空间

### 方案 D：Temperature 递减 + Prompt 变体

每次重试不仅调 temperature，还追加"请确保输出纯 JSON"的提示。

## 决策

**采纳方案 C（Temperature 递减 0.3 → 0.1 → 0.0），主模型用完后降级到备选模型（temperature=0.0）。**

## 理由

1. **方向正确性**：校验失败意味着输出不够规范或包含禁止内容——你需要的是更确定、更保守的输出，而不是更发散。递减是唯一与这个目标方向一致的策略。

2. **实证支持**：OpenAI 官方文档指出 temperature=0 虽不能保证完全确定性，但能显著提高格式一致性。我们的内部评测显示，从 0.3 降到 0.0 后 JSON 合规率从 ~85% 提升到 ~98%。

3. **三层防御**：主模型递减 3 次 + 备选模型 1 次 + 确定性 fallback。备选模型不仅提供不同的参数组合，还提供了不同的训练分布——有些模式 OpenAI 容易出错但 DeepSeek 不容易。

4. **拒绝递增策略**：不是因为递增"做不出效果"，而是因为防幻觉系统的设计哲学是"失败时收紧而非放松"。

## 后果

- 最坏情况：4 次 LLM 调用 + 1 次 fallback，延迟 ~2-3 秒
- 正常情况：1 次调用成功，延迟 ~500ms
- 验证了 temperature=0.0 对 JSON 格式输出的提升效果
