## 定位与边界

产品主线为诊断对话、知识库与检索质量、Agent 流程管理。一级路由流程与诊断流程继续共用现有管理入口。

第一轮删除不再被主线调用的实现，不进行数据库删表或重写执行内核。TypeScript 继续提供主 API，Python 提供配置诊断流程执行；独立 Python 聊天、旧诊断执行路径与记忆缓存的迁移另行完成。

## 设计与调用关系检查

- 通用 Workflow 的调用方仅为其 HTTP 路由；当前管理端与 SDK 没有消费者。移除路由、执行模块、专用类型和指标；保留历史迁移与数据表，避免隐式丢失旧运行数据。
- Team 被 TypeScript 默认诊断路径调用。移除通用 Team HTTP 管理入口及依赖它的调试页，保留内部诊断执行器与数据模型，不能随路由一起删除。
- 当前对话页面使用 `useAgentChatStream`。旧悬浮客服、旧 Agent hook 及其专用 store、SSE 解析器没有应用入口，删除这条孤立依赖链。
- 图片解析继续服务文档摄取；音频和视频解析没有当前上传向导入口，移除其解析器与专用元数据。避免改动图片模型配置引起无关兼容问题。
- 保留负反馈收集与列表，归入知识库；删除只展示会话计数的统计 UI。Langfuse 保留后端集成，管理端以外部链接打开，不再占用独立页面。
- 已有一级路由流程及工作区未提交修改继续保留，不改写其流程、发布和权限逻辑。

本地静态检查确认上述删除边界；未进行独立 Agent 架构评审。不删除仍有内部消费者的 Team、Router、RAG、Memory 实现。

## 验证计划

- TypeScript 服务、共享包、两个前端的类型检查与构建。
- 服务端回归覆盖诊断、配置桥接、一级路由、权限、知识摄取和引用。
- 浏览器回归覆盖精简后导航、反馈入口以及两类流程的编辑器入口。
- 检查删除文件的残留导入、工作区差异与旧 API 是否仍被挂载。
- 不执行数据库迁移，不启动真实模型评测，不修改既有未提交变更的业务语义。

## 后续迁移

1. 让默认诊断也使用内置 Flow，完成等价回归后移除内部 Team 和旧诊断图。
2. 确定唯一聊天、RAG 和记忆实现，再裁剪 Python 重复公共 API。
3. 用固定数据集产出检索命中率、诊断正确率、时延与成本报告；基于这些结果决定路由层级和缓存是否值得保留。

这些工作涉及行为迁移，本轮不以隐藏入口代替完成迁移。
